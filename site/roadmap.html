What Davy does, and what comes next.

Each shipped part carries the day it landed on main. The same list is in roadmap.json, which this page is written from, and the changelog has every detail.

Next

In about this order.

  1. A cold tier for old logs

    Old days of logs become compressed segments that stay searchable and can live on object storage.

  2. Sign in with any OIDC provider

    People sign in to the web UI through the identity provider the team already uses.

  3. Scoped API tokens

    A token can be limited to some projects and to reading, so an agent gets only the access it needs.

  4. An audit log of what agents changed

    Every change an agent or a person makes, such as a resolved issue or a new drop rule, is recorded with who made it.

  5. Backup and restore

    One command takes a consistent copy of a running server and another brings it back.

Later

  1. A hosted Davy, run by us

    The same Davy, for teams that would rather not run a server.

On main

Shipped since the last release, in the next one.

  1. Daily quotas and spike protection

    Each project gets a daily limit, so one runaway app cannot fill the disk for the others.

    Nov 26

  2. A usage page in the web UI

    One page shows the disk used and free, the day it fills, what each project sends and where it could take less.

    Nov 26

  3. Agents propose drop rules

    An agent stages a drop rule that only counts what it would drop, and a person makes it live.

    Nov 26

  4. Drop rules with shadow mode

    Log lines nobody needs are dropped before they are stored, after a shadow run shows what a rule would drop.

    Nov 25

  5. A savings view

    Davy lists the log patterns with the most bytes, logs kept longer than anyone reads and the noisiest issues, with the command that frees the space.

    Nov 25

  6. Search history

    Davy records the log searches people and agents run, so it can tell which logs nobody reads.

    Nov 25

  7. Discard an issue

    A noisy issue stops storing new events and only counts them.

    Nov 25

  8. Davy watches itself

    Davy stores its own warnings and errors in a project of its own, where they can be searched like any app's.

    Nov 25

  9. Logs from Vercel

    A Vercel log drain sends a deployment's logs straight to Davy, with its signature checked.

    Nov 25

  10. A disk forecast

    Davy tells you the day the disk fills at the current rate, per project, from the first hour of data.

    Nov 25

  11. Usage counters

    Davy counts what each project sends per day and signal, and keeps the counts for 400 days.

    Nov 24

  12. Log patterns

    Log lines are grouped by shape, so you see which kinds of line fill the logs.

    Nov 24

  13. Scrubbing on by default

    Passwords, keys, card numbers and IP addresses are removed on the server before anything is stored.

    Nov 24

  14. Retention per project

    Each project keeps its logs and its errors for as many days as it needs.

    Nov 24

  15. Connect an app in one command

    One command prints the SDK setup for an app and a command that sends a test event.

    Nov 23

  16. Release health and user feedback

    Davy shows crash-free sessions per release, and what users wrote in the feedback widget next to the issue.

    Nov 23

  17. Cron check-ins

    A scheduled job that reports in becomes a monitor that alerts when a run is late or fails.

    Nov 23

0.1.0

Released Nov 23, 2026.

  1. A web UI for one team

    People read issues, logs and uptime in a browser, behind a password.

  2. Signed releases

    Every release ships with checksums, an SBOM per binary, build provenance and a signed image.

  3. Install by prompt

    An agent installs Davy and connects an app from one prompt.

  4. Uptime checks and alerts

    HTTP checks and heartbeats alert by e-mail, Slack or a signed webhook when something stops answering.

  5. Source maps

    Minified JavaScript stack traces point back at the lines you wrote.

  6. Tools for agents

    An MCP server and a CLI let an agent search errors and logs, read an issue and mark it fixed.

  7. Logs

    Logs from OpenTelemetry, Logtail shippers and Sentry's logger, with full-text search, on a store picked by a published benchmark.

  8. Errors from the Sentry SDKs

    Point an existing Sentry SDK at Davy and errors arrive grouped into issues.
